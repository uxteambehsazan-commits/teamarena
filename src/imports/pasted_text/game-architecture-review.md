# بخش ۱ — بررسی هسته فعلی

ابتدا کل پروژه را بررسی کن و مشخص کن:

* تمام ۱۶ هسته/بازی مورد انتظار در پروژه وجود دارند یا خیر.
* بازی‌های تب «بازی‌های عمومی» کدام هستند.
* بازی‌های تب «بازی‌های آنلاین بهسازانی» کدام هستند.
* هر کارت بازی به کدام Game ID، Route، Component، Screen، Engine یا Game Controller متصل است.
* آیا Game IDها تکراری یا اشتباه هستند.
* آیا Routeهای بازی‌ها با یکدیگر تداخل دارند.
* آیا Component یک بازی به اشتباه Component بازی دیگری را صدا می‌زند.
* آیا بازی‌های آنلاین بهسازانی به‌جای Engine اختصاصی خودشان، Engine بازی‌های عمومی را فراخوانی می‌کنند.
* آیا انتخاب کارت بازی صرفاً UI را تغییر می‌دهد ولی منطق بازی همچنان به یک بازی پیش‌فرض متصل است.
* آیا fallback اشتباه باعث اجرای «استاد حافظه» می‌شود.

### قانون بسیار مهم

به هیچ عنوان برای بازی‌های آنلاین بهسازانی از Engine یا Game Component بازی‌های عمومی به‌عنوان fallback استفاده نکن.

اگر هسته یکی از ۸ بازی وجود ندارد، باید هسته واقعی آن بازی ایجاد شود؛ نه اینکه یک بازی دیگر نمایش داده شود.

# بخش ۱۸ — معیار پذیرش نهایی

کار زمانی تمام شده محسوب می‌شود که:

* هر ۸ بازی هسته مستقل داشته باشند.
* هر ۸ بازی Game ID مستقل داشته باشند.
* هر ۸ بازی Route مستقل داشته باشند.
* هر ۸ بازی Lobby مستقل داشته باشند.
* هر ۸ بازی Rules مستقل داشته باشند.
* هر ۸ بازی State مستقل داشته باشند.
* هر ۸ بازی Engine مستقل داشته باشند.
* بازی‌های عمومی بدون تغییر و سالم باقی بمانند.
* انتخاب «مافیای بهسازانی» هرگز «استاد حافظه» را اجرا نکند.
* انتخاب هیچ‌یک از ۸ بازی باعث نمایش بازی‌های عمومی نشود.
* Navigation از طریق Game Registry انجام شود.
* هیچ fallback از بازی‌های آنلاین بهسازانی به بازی‌های عمومی وجود نداشته باشد.
* تمام ۱۶ بازی موجود در معماری نهایی قابل شناسایی باشند.
* اگر یکی از ۸ هسته واقعاً در پروژه وجود ندارد، همان هسته را طبق مشخصات بالا ایجاد کن.
* در پایان، یک گزارش فنی کوتاه ارائه کن که برای هر ۱۶ بازی مشخص کند:

  * Game ID
  * Engine
  * Route
  * وضعیت هسته
  * وضعیت تست
  * وابستگی‌های مشترک
  * هر مشکل اصلاح‌شده

## دستور نهایی

اول پروژه را بررسی کن؛ سپس معماری موجود را اصلاح کن؛ سپس هسته‌های ناقص ۸ بازی آنلاین بهسازانی را ایجاد کن؛ سپس Mapping و Navigation را اصلاح کن؛ سپس تمام مسیرها را تست کن.

**هرگز برای رفع خطای یک بازی، بازی دیگری را به‌عنوان جایگزین نمایش نده.**

هدف نهایی این است که کاربر با انتخاب هر بازی، دقیقاً همان بازی را اجرا کند و هیچ‌گونه Cross-Game Routing یا نمایش بازی اشتباه وجود نداشته باشد.
