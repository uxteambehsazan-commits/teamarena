بازی «نقاشی» را از نظر GAME CORE و Multiplayer Architecture به‌صورت کامل بازطراحی کن.

مهم:
این تغییر فقط مربوط به ظاهر UI نیست. هسته، State Management، Role Management، Game Flow و ارتباط بین بازیکنان باید بر اساس یک بازی آنلاین چندنفره واقعی طراحی شود.

هدف بازی:
در هر Round فقط یک بازیکن نقش «نقاش» دارد و سایر بازیکنان نقش «حدس‌زننده» دارند.

در هر Round:
1. یک بازیکن به‌صورت نوبتی به عنوان نقاش انتخاب شود.
2. فقط نقاش کلمه/موضوع اصلی را ببیند.
3. نقاش باید کلمه را با ابزار نقاشی روی Canvas رسم کند.
4. سایر بازیکنان فقط نقاشی زنده نقاش را ببینند.
5. حدس‌زنندگان هرگز نباید خود کلمه اصلی را ببینند.
6. حدس‌زنندگان باید بتوانند حدس خود را وارد و ارسال کنند.
7. سیستم باید حدس‌ها را به‌صورت Real-Time بین بازیکنان مدیریت کند.
8. تایمر برای همه بازیکنان همگام و یکسان باشد.
9. پس از پایان زمان یا حدس صحیح، Round خاتمه پیدا کند.
10. سپس نقش نقاش به بازیکن بعدی منتقل شود.

--------------------------------------------------
1. ROLE-BASED VIEW
--------------------------------------------------

در هر Round دقیقاً دو نوع View وجود داشته باشد:

A) DRAWER / نقاش

نقاش باید ببیند:
- کلمه اصلی
- موضوع/دسته‌بندی
- تایمر
- Canvas نقاشی
- ابزارهای نقاشی
- رنگ‌ها
- پاک‌کن
- پاک کردن Canvas
- وضعیت Round
- تعداد بازیکنان
- وضعیت حدس‌های سایر بازیکنان، بدون نمایش کلمه اصلی برای آنها

نقاش باید بتواند:
- روی Canvas نقاشی کند
- خطوط را Real-Time برای سایر بازیکنان ارسال کند
- نقاشی خود را پاک کند
- تا پایان تایمر نقاشی را ادامه دهد

مهم:
کلمه اصلی فقط و فقط برای نقاش قابل مشاهده باشد.

--------------------------------------------------
2. GUESSER / حدس‌زنندگان
--------------------------------------------------

بازیکنانی که نقاش نیستند باید View کاملاً متفاوتی داشته باشند.

حدس‌زنندگان نباید به هیچ عنوان موارد زیر را ببینند:
- کلمه اصلی
- متن کلمه اصلی
- پاسخ صحیح
- UI مخصوص نقاش
- Canvas کنترل‌پذیر
- ابزارهای نقاشی
- هر داده‌ای که بتواند کلمه اصلی را مستقیماً افشا کند

حدس‌زننده فقط این موارد را ببیند:

- نقاشی زنده نقاش
- موضوع / Category
- تایمر
- تعداد حروف کلمه

مثلاً اگر کلمه «کامپیوتر» باشد:

موضوع:
فناوری

تعداد حروف:
۸ حرف

اما خود عبارت:
«کامپیوتر»

هرگز برای Guessers نمایش داده نشود.

--------------------------------------------------
3. REAL-TIME DRAWING
--------------------------------------------------

Canvas نقاش باید Real-Time باشد.

هر حرکت قلم نقاش باید به سایر بازیکنان ارسال شود.

وقتی نقاش خطی رسم می‌کند:

Drawer:
→ خط را روی Canvas رسم می‌کند.

Guessers:
→ همان خط را تقریباً همزمان روی Canvas خود مشاهده می‌کنند.

از ارسال Snapshot کامل Canvas در هر تغییر خودداری کن.
Drawing باید به صورت Stroke / Drawing Event مدیریت شود تا:
- Performance بهتر شود
- مصرف داده کاهش پیدا کند
- Synchronization بهتر شود
- امکان Reconnect وجود داشته باشد

ساختار منطقی Drawing Event:

{
  playerId,
  roundId,
  strokeId,
  points,
  color,
  width,
  timestamp
}

--------------------------------------------------
4. GAME STATE
--------------------------------------------------

برای بازی یک State Machine واقعی ایجاد کن.

States:

LOBBY
↓
ROUND_START
↓
WORD_ASSIGNED
↓
DRAWING
↓
GUESSING
↓
ROUND_END
↓
NEXT_DRAWER
↓
DRAWING
...
↓
GAME_END

هر بازیکن باید State مربوط به همان Room و Round را دریافت کند.

--------------------------------------------------
5. ROUND MANAGEMENT
--------------------------------------------------

در ابتدای هر Round:

1. سیستم Drawer بعدی را انتخاب کند.
2. یک Word جدید انتخاب شود.
3. Word فقط برای Drawer ارسال شود.
4. Category برای همه ارسال شود.
5. Letter Count برای Guessers ارسال شود.
6. Timer برای همه شروع شود.
7. Canvas پاک و آماده Round جدید شود.

مثال:

Round 1
Drawer:
Player A

Word:
«کامپیوتر»

Category:
«فناوری»

Timer:
60 seconds

Drawer:
Word = کامپیوتر

Guessers:
Category = فناوری
Letters = ۸
Word = HIDDEN

--------------------------------------------------
6. GUESS SYSTEM
--------------------------------------------------

Guessers باید یک Input برای ثبت حدس داشته باشند.

مثال:

[ حدس خود را وارد کنید... ]

[ ارسال ]

وقتی بازیکن حدس خود را ارسال کرد:

- Guess به Server/Game State ارسال شود.
- سایر بازیکنان بتوانند وضعیت Guess را ببینند، اما در صورت نیاز نام ارسال‌کننده و متن حدس بر اساس قوانین بازی مدیریت شود.
- اگر حدس صحیح بود:
    Round فوراً یا طبق Rule تعریف‌شده پایان یابد.
- امتیاز به بازیکن صحیح داده شود.
- Drawer نیز امتیاز دریافت کند.
- نتیجه Round برای همه نمایش داده شود.

--------------------------------------------------
7. ANTI-CHEAT / INFORMATION ISOLATION
--------------------------------------------------

این بخش بسیار مهم است.

کلمه اصلی نباید صرفاً با CSS یا hidden element از Guessers مخفی شود.

Word باید از نظر Game State / Data Model نیز Role-Based باشد.

یعنی:

Drawer State:
{
  role: "drawer",
  word: "کامپیوتر"
}

Guesser State:
{
  role: "guesser",
  word: null,
  category: "فناوری",
  letterCount: 8
}

هرگز Word را داخل State مشترک Guessers قرار نده.

نباید این اتفاق رخ دهد:

{
  word: "کامپیوتر",
  visible: false
}

چون در این حالت اطلاعات Word همچنان در Client بازیکن وجود دارد.

اطلاعات حساس باید فقط به Role مجاز ارسال شود.

--------------------------------------------------
8. TURN SYNCHRONIZATION
--------------------------------------------------

نقاشی باید کاملاً نوبتی باشد.

مثال 4 بازیکن:

Player A
Player B
Player C
Player D

Round 1:
A = Drawer
B/C/D = Guessers

Round 2:
B = Drawer
A/C/D = Guessers

Round 3:
C = Drawer
A/B/D = Guessers

Round 4:
D = Drawer
A/B/C = Guessers

هیچ بازیکنی نباید بتواند خارج از نوبت وارد حالت Drawer شود.

Drawer باید توسط Game Engine تعیین شود، نه توسط Client.

--------------------------------------------------
9. TIMER SYNCHRONIZATION
--------------------------------------------------

Timer نباید به‌صورت مستقل روی هر دستگاه اجرا شود.

زمان Round باید از یک Server/Game State مشترک محاسبه شود.

مثلاً:

roundStartedAt
roundDuration
remainingTime

همه بازیکنان باید یک Timer هماهنگ داشته باشند.

اگر یک بازیکن صفحه را Refresh کرد:
- Round دوباره از ابتدا شروع نشود.
- نقش بازیکن حفظ شود.
- زمان واقعی باقی‌مانده نمایش داده شود.
- Drawing فعلی در صورت امکان بازیابی شود.

--------------------------------------------------
10. RECONNECT
--------------------------------------------------

اگر بازیکن اینترنت خود را از دست داد:

Disconnected State

سپس بعد از اتصال مجدد:

Reconnect
↓
Identify Player
↓
Identify Room
↓
Identify Round
↓
Restore Role
↓
Restore Timer
↓
Restore Drawing State
↓
Continue Game

اگر بازیکن Drawer باشد:
- امکان ادامه نقاشی داشته باشد.

اگر Guesser باشد:
- همان Canvas فعلی را ببیند.
- بتواند دوباره حدس بزند.

امتیازها باید برای همه بازیکنان Synchronize شوند.

--------------------------------------------------
16. SINGLE PLAYER VS ONLINE
--------------------------------------------------

این بازی باید دو Mode کاملاً متفاوت داشته باشد:

SINGLE PLAYER:
بازی روی یک دستگاه و مطابق منطق بازی تک‌دستگاهی فعلی.

ONLINE:
هر بازیکن با دستگاه خودش وارد Room می‌شود.

در Online Mode:

هر Client فقط View و Role مجاز خودش را دریافت کند.

به هیچ عنوان نسخه فعلی که تمام بازی روی یک Device اجرا می‌شود را به عنوان Multiplayer در نظر نگیر.

playerId

--------------------------------------------------
19. FINAL ACCEPTANCE CRITERIA
--------------------------------------------------

بازی فقط زمانی موفق تلقی شود که:

✓ هر بازیکن با دستگاه مستقل بازی کند
✓ فقط Drawer Word را ببیند
✓ Guessers فقط Category + Letter Count + Timer را ببینند
✓ Guessers Drawing زنده Drawer را ببینند
✓ Drawing بین تمام Clientها Synchronize باشد
✓ Timer Synchronize باشد
✓ Turn Order Synchronize باشد
✓ Guessها Synchronize باشند
✓ Score Synchronize باشد
✓ Refresh باعث از دست رفتن Round نشود
✓ Reconnect مدیریت شود
✓ اطلاعات Word به Client Guessers ارسال نشود
✓ هیچ بازیکنی نتواند Role بازیکن دیگر را جعل کند
✓ Roundها به‌صورت واقعی نوبتی اجرا شوند
✓ پایان Round برای همه همزمان باشد
✓ Round بعدی به‌صورت خودکار شروع شود

در نهایت تمام Flow بازی نقاشی را از ورود بازیکنان تا پایان چندین Round به‌صورت End-to-End تست کن و هر مشکل مربوط به Multiplayer، Synchronization، Role Isolation، State Management، Performance یا UI را قبل از اعلام تکمیل بودن بازی اصلاح کن.

این تغییر باید فقط روی بازی «نقاشی» اعمال شود و سایر بازی‌ها و منطق آنها بدون درخواست صریح تغییر نکنند.
