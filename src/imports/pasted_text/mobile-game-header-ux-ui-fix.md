MASTER MOBILE GAME HEADER UX/UI FIX
PRODUCT: «میدان هم‌تیمی‌ها»
TARGET: In-Game Mobile Header
REFERENCE: Use the attached screenshot as the exact reference for the current problematic state.

============================================================
OBJECTIVE
============================================================

هدر بالای صفحه بازی در نسخه فعلی بیش از حد متراکم است.

در موبایل، موارد زیر همگی در یک نوار بسیار باریک قرار گرفته‌اند:

- امتیاز
- آواتار / اطلاعات بازیکن
- تعداد / شماره راند
- وضعیت بازیکنان
- آیکن‌های وضعیت
- Progress indicators

نتیجه:
- خوانایی پایین است.
- عناصر به هم چسبیده‌اند.
- سلسله‌مراتب بصری مشخص نیست.
- اطلاعات مهم با اطلاعات فرعی قاطی شده‌اند.
- فضای کافی برای Touch وجود ندارد.
- در موبایل احتمال Overlap و Clipping وجود دارد.

این Header را از نظر UX/UI بازطراحی کن.

IMPORTANT:
منطق بازی، State، Score، Timer، Player State و Game Engine را تغییر نده.

فقط Presentation / Layout / Responsive Behavior را اصلاح کن.

============================================================
1. REMOVE THE SINGLE-DENSE-ROW DESIGN
============================================================

هدر فعلی که همه اطلاعات را در یک خط قرار داده است حذف شود.

به هیچ عنوان:

Score + Player + Round + Progress + Status

را در یک ردیف بسیار باریک قرار نده.

Header باید به چند ناحیه واضح تقسیم شود.

============================================================
2. NEW MOBILE HEADER STRUCTURE
============================================================

برای موبایل از یک ساختار دو لایه استفاده کن.

LAYOUT:

┌─────────────────────────────────┐
│  Player / Score     Round       │
│                                 │
│          14                      │
│         ثانیه                   │
│                                 │
│  ● ● ● ● ● ● ●                 │
└─────────────────────────────────┘

اما Header نباید ارتفاع بیش از حد داشته باشد.

ساختار پیشنهادی:

ROW 1:
Player information + Score

ROW 2:
Game progress / round status

ROW 3:
Main Timer فقط در صورتی که بازی Timer فعال دارد.

اگر Timer در Body اصلی بازی نمایش داده می‌شود،
آن را دوباره در Header تکرار نکن.

============================================================
3. PLAYER / SCORE AREA
============================================================

اطلاعات بازیکن و امتیاز باید از Progress جدا شود.

مثلاً:

[Avatar]  نام بازیکن
          امتیاز: 330

در سمت مقابل:

راند ۱ از ۵

یا:

راند ۱

از نمایش چند اطلاعات ریز کنار هم خودداری کن.

Score باید خوانا باشد.

مثلاً:

«۳۳۰»
«امتیاز»

به جای:

🏆330

از ترکیب نامفهوم Icon + Number در فضای بسیار فشرده استفاده نکن.

============================================================
4. ROUND INFORMATION
============================================================

شماره راند باید واضح و مستقل باشد.

مثلاً:

«راند ۱ از ۵»

یا اگر سیستم تعداد کل راند را نمی‌داند:

«راند ۱»

این اطلاعات نباید با Player Score یا Timer ترکیب شود.

از فونت خوانا استفاده کن.

============================================================
5. TIMER
============================================================

Timer مهم‌ترین اطلاعات لحظه‌ای بازی است.

اگر Timer در Header قرار دارد:

عدد Timer را بزرگ و واضح نمایش بده.

مثلاً:

14
ثانیه

عدد باید حداقل به اندازه‌ای باشد که در موبایل با یک نگاه خوانده شود.

از نمایش:

14 ثانیه

در فونت بسیار کوچک خودداری کن.

Timer نباید کنار 5 یا 6 اطلاعات دیگر قرار بگیرد.

============================================================
6. PROGRESS INDICATOR
============================================================

آیکن‌های متعدد فعلی که در بالای صفحه دیده می‌شوند بیش از حد فشرده‌اند.

Progress را به یک Component مستقل تبدیل کن.

مثلاً:

● ● ● ● ━ ━

یا:

1  2  3  4  5

با Stateهای:

Completed
Current
Upcoming

اما:

Progress Indicator نباید فضای زیادی اشغال کند.

از آیکن‌های بزرگ یا متن‌های طولانی استفاده نکن.

============================================================
7. PLAYER STATUS
============================================================

اگر وضعیت بازیکنان نمایش داده می‌شود، آن را از Header اصلی جدا کن.

به جای نمایش چند تیک و آیکن ریز در Header:

یک Indicator ساده:

«۵ نفر آماده»
یا
«۳ نفر در حال بازی»

استفاده کن، فقط اگر این اطلاعات واقعاً برای همان بازی ضروری است.

اگر Player Status برای تصمیم‌گیری کاربر لازم نیست،
آن را از Header حذف کن و در یک بخش Secondary / Expandable قرار بده.

12. ICON RULE
============================================================

از تعداد زیاد Icon در Header خودداری کن.

هر Icon باید:

- واضح
- ساده
- دارای فضای کافی
- دارای Touch Area مناسب

باشد.

Iconهای تزئینی را از Header حذف کن اگر باعث تراکم می‌شوند.

============================================================
