صفحه «انتخاب بازی‌ها» را به‌صورت کامل بازطراحی و بهینه‌سازی کن، بدون اینکه هسته، قوانین یا محتوای اصلی بازی‌های موجود بدون دلیل تغییر کند.

### 1. بازطراحی صفحه انتخاب بازی‌ها

صفحه انتخاب بازی‌ها را با یک UI مدرن، حرفه‌ای، جذاب و Game Hub محور طراحی کن.

* Layout کاملاً Grid-based و منظم باشد.
* کارت‌های بازی‌ها ساختار یکپارچه و مدرن داشته باشند.
* Hierarchy بصری واضح بین عنوان بازی، توضیح کوتاه، تعداد بازیکنان و وضعیت بازی ایجاد شود.
* هر بازی یک Card مستقل با:

  * تصویر/Illustration اختصاصی
  * نام بازی
  * توضیح بسیار کوتاه
  * تعداد بازیکنان
  * نوع بازی: تک‌نفره / چندنفره
  * وضعیت: آماده بازی / در حال توسعه در صورت وجود
  * CTA واضح «شروع بازی»
* از فضای خالی مناسب، Radius مدرن، Shadow ظریف و Micro-interaction استفاده کن.
* کارت‌ها در Hover و Press حالت تعاملی داشته باشند.
* بازی منتخب یا آخرین بازی انجام‌شده می‌تواند با Highlight ظریف نمایش داده شود.
* از شلوغی بصری جلوگیری کن.
* صفحه باید حس یک «Game Hub» مدرن داشته باشد، نه یک لیست ساده از لینک‌ها.

### 2. Responsive Design

صفحه را برای Desktop، Tablet و Mobile کاملاً Responsive کن.

Desktop:

* Grid چندستونه
* استفاده بهینه از عرض صفحه
* فاصله‌گذاری منظم

Tablet:

* کاهش تعداد ستون‌ها
* حفظ اندازه مناسب کارت‌ها

Mobile:

* Grid تک‌ستونه یا دو ستون بسته به عرض
* هیچ متن، دکمه، Badge یا عنوانی نباید از Card خارج شود.
* هیچ متن فارسی نباید روی متن دیگر قرار بگیرد.
* هیچ Button نباید بریده یا خارج از viewport شود.
* هیچ Horizontal Overflow ایجاد نشود.
* ارتفاع کارت‌ها در صورت نیاز Adaptive باشد.
* متن‌های طولانی با Line Clamp مناسب مدیریت شوند.

### 3. RTL و Typography

کل رابط فارسی و RTL باشد.

تمام این موارد را بررسی و اصلاح کن:

* تداخل کلمات فارسی
* شکستن نام بازی‌ها
* فاصله نام و توضیح
* Alignment اشتباه
* تداخل Badge و CTA
* فاصله اعداد فارسی و متن
* نمایش صحیح اعداد فارسی
* نمایش صحیح متن در Mobile
* جلوگیری از Overflow در عرض‌های کوچک

هیچ متن یا کامپوننتی نباید در هیچ Breakpoint روی عنصر دیگری قرار بگیرد.

### 4. تست کامل تمام بازی‌ها

بعد از بازطراحی، تمام بازی‌های موجود را End-to-End بررسی کن.

برای هر بازی این موارد را تست کن:

* ورود به بازی
* شروع بازی
* Restart
* برگشت به Game Hub
* تغییر حالت بازی
* انتخاب بازیکن
* تغییر نوبت
* ثبت حرکت
* محاسبه امتیاز
* پایان بازی
* نمایش نتیجه
* بازی مجدد
* مدیریت وضعیت‌های Invalid
* جلوگیری از ثبت حرکت غیرمجاز
* جلوگیری از دوبار ثبت شدن یک حرکت
* جلوگیری از گیر کردن بازی
* بررسی تمام Buttonها و Interactive Elementها
* بررسی وضعیت‌های Empty / Loading / Error / Success در صورت وجود

هیچ تغییر ظاهری نباید باعث شکستن Logic بازی شود.

### 5. تست هسته و منطق بازی‌ها

Game Logic تمام بازی‌ها را دوباره بررسی کن.

به‌خصوص موارد زیر را بررسی کن:

* State Management
* Turn Management
* Win Condition
* Lose Condition
* Draw Condition
* Score Calculation
* Game Reset
* Round Reset
* جلوگیری از حرکت خارج از قوانین
* جلوگیری از Race Condition
* جلوگیری از Double Click / Double Move
* هماهنگی UI State با Game State

اگر UI چیزی را نمایش می‌دهد که با وضعیت واقعی Game State متفاوت است، منطق را اصلاح کن.

### 6. بررسی ویژه بازی دوز (Tic-Tac-Toe)

بازی دوز را از ابتدا تا انتها مجدداً تست و Audit کن.

#### قوانین بازی

اطمینان حاصل کن:

* صفحه 3×3 صحیح باشد.
* فقط خانه‌های خالی قابل انتخاب باشند.
* بازیکن و AI به‌صورت صحیح نوبت بگیرند.
* بعد از هر حرکت، نوبت به بازیکن صحیح منتقل شود.
* بعد از Win بازی متوقف شود.
* بعد از Draw بازی متوقف شود.
* پس از پایان بازی امکان حرکت جدید وجود نداشته باشد.
* Reset تمام Stateهای قبلی را پاک کند.
* نتیجه هر Round صحیح محاسبه شود.

تمام Winning Combinationها را تست کن:

* سه خانه افقی
* سه خانه عمودی
* قطر اصلی
* قطر فرعی

تمام حالت‌های Win برای Player و AI باید بررسی شوند.

### 7. تست هوش مصنوعی دوز

AI بازی دوز را به‌صورت جدی بررسی و اصلاح کن.

AI نباید حرکت تصادفی و غیرمنطقی داشته باشد، مگر اینکه Difficulty عمداً Easy باشد.

حداقل این منطق را بررسی کن:

1. اگر AI بتواند در حرکت فعلی برنده شود، همان حرکت را انتخاب کند.
2. اگر بازیکن در حرکت بعدی بتواند برنده شود، AI باید آن حرکت را Block کند.
3. اگر امکان ایجاد Fork وجود دارد، AI آن را در نظر بگیرد.
4. اولویت‌های استراتژیک منطقی برای Corner و Center رعایت شود.
5. AI نباید حرکت غیرمجاز انجام دهد.
6. AI نباید روی خانه پرشده حرکت کند.
7. AI نباید بیشتر از یک حرکت در هر Turn انجام دهد.
8. AI نباید بعد از پایان بازی حرکت کند.
9. AI نباید وارد Loop یا وضعیت Deadlock شود.

### 8. سرعت و Timing هوش مصنوعی

سرعت AI را بررسی و استاندارد کن.

AI نباید:

* بیش از حد سریع و غیرقابل‌درک حرکت کند.
* آن‌قدر کند باشد که کاربر تصور کند بازی خراب شده.
* چند حرکت پشت سر هم انجام دهد.
* قبل از پایان Animation حرکت قبلی، حرکت جدید ثبت کند.

یک Delay کوتاه و طبیعی برای حرکت AI ایجاد کن؛ حدود 400 تا 900 میلی‌ثانیه، متناسب با وضعیت بازی.

در زمان فکر کردن AI:

* UI باید وضعیت واضح داشته باشد.
* مثلاً نمایش «در حال فکر کردن…»
* Board در صورت نیاز موقتاً غیرقابل تعامل شود.
* بعد از انتخاب حرکت، State فوراً Sync شود.

### 9. Difficulty

اگر بازی دوز دارای Difficulty است، عملکرد هر سطح را بررسی کن:

Easy:
حرکت‌های ساده و قابل پیش‌بینی، اما کاملاً قانونی.

Medium:
Block کردن حرکت‌های خطرناک و انتخاب حرکت‌های منطقی.

Hard:
بازی استراتژیک و بدون اشتباه واضح؛ AI نباید به‌راحتی شکست بخورد.

سطوح Difficulty نباید صرفاً با تغییر Delay شبیه‌سازی شوند؛ تفاوت باید در منطق تصمیم‌گیری AI باشد.

### 10. تست Performance

کل پروژه را برای Performance بررسی کن.

بررسی کن:

* Renderهای غیرضروری
* State Updateهای اضافی
* Event Listenerهای تکراری
* Timerهای باقی‌مانده بعد از پایان بازی
* Memory Leak
* Animationهای سنگین
* اجرای چندباره AI
* Click Handlerهای Duplicate

بعد از Restart یا خروج از بازی، Timerها و Listenerهای مربوط به بازی قبلی نباید فعال باقی بمانند.

* در زمان Turn هوش مصنوعی حرکت کند.
* بعد از پایان بازی حرکت ثبت کند.
* یک خانه را دوبار انتخاب کند.
* با Double Click دو حرکت ثبت کند.
* چندبار هم‌زمان Restart کند.
* هنگام Transition باعث خراب شدن State شود.

### 15. Visual QA

هر موردی که باعث:

* Overlap
* Clipping
* Overflow
* Misalignment
* Broken Grid
* Text Collision
* Incorrect Spacing
* Broken Responsive Layout
* Unclear CTA

می‌شود را اصلاح کن.

### 16. Regression Test

پس از تمام اصلاحات، دوباره تمام بازی‌ها را اجرا کن.

هدف فقط زیبایی UI نیست؛ باید مطمئن شوی تغییرات جدید هیچ‌کدام از بازی‌های قبلی را خراب نکرده‌اند.

### قانون مهم

بدون درخواست من:

* بازی جدید اضافه نکن.
* قوانین بازی‌های موجود را تغییر نده.
* محتوای اصلی بازی‌ها را حذف نکن.
* بخش‌های سالم پروژه را بازطراحی نکن.
* فقط مشکلات واقعی را اصلاح کن.
* UI جدید باید با هویت بصری فعلی پروژه هماهنگ باشد.

### خروجی نهایی

در پایان پروژه باید:

1. صفحه انتخاب بازی‌ها مدرن، Grid-based و Responsive باشد.
2. تمام بازی‌ها بدون خطای UI اجرا شوند.
3. هیچ Text Collision در Desktop یا Mobile وجود نداشته باشد.
4. هیچ Overflow ناخواسته وجود نداشته باشد.
5. Game Logic تمام بازی‌ها سالم باشد.
6. بازی دوز از نظر قوانین کامل تست شده باشد.
7. AI دوز از نظر Strategy، سرعت، Turn و Difficulty تست و اصلاح شده باشد.
8. Restart و خروج از بازی State قبلی را باقی نگذارند.
9. Performance و Interactionها بررسی شده باشند.
10. بعد از اصلاحات، Regression Test کامل انجام شده باشد.

قبل از پایان کار، خودت را در نقش یک QA Tester و یک کاربر واقعی قرار بده و تمام Flowهای اصلی را چند بار اجرا کن. هر ایرادی که پیدا می‌کنی ابتدا ریشه آن را در Logic یا UI مشخص کن و سپس اصلاح کن؛ فقط ظاهر مشکل را Patch نکن.
